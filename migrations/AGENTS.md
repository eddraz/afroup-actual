# D1 Migrations DOX

## Purpose

- `migrations/` contains the ordered D1 schema, seed, and data-transform history for `afroup-db`.

## Ownership

- Owns the numbered SQL migrations configured by root `wrangler.jsonc`.
- Root `docs/` owns the official source PDF/material, and root `scripts/` owns the seed generator that writes `0002_seed_official_guide.sql`.

## Local Contracts

- Numeric filename order is the application order; preserve the sequence and every prerequisite between schema, seed, and transform migrations.
- `0001` creates the base schema and initial departments. `0002` is generated by `scripts/generate_official_seed.py` from the official guide material under `docs/`.
- `0003` and `0004` add admin credentials and abuse tracking. `0005` reclassifies seeded Buenaventura rows after the seed exists.
- `0006`, `0007`, and `0008` successively create, convert, and deduplicate the public `information` field. `0008` relies on seeded row IDs and the official-source marker.

## Work Guidance

- Add new changes with the next numeric prefix; do not reorder dependent transforms.
- Update `scripts/generate_official_seed.py` and regenerate `0002_seed_official_guide.sql` when its generated official seed changes instead of hand-editing generated rows.
- Keep corrective data migrations after the schema and seed state they expect.

## Verification

- `bun run db:migrate:local` is the current migration check.

## Manual D1 apply notes

- If `wrangler d1 migrations apply` fails on `0010_admin_rbac.sql` with "near (": syntax error", the cause is D1's lack of support for `VALUES (...)` as a derived table. The fix lives in the migration file itself (`UNION ALL` of `SELECT` literals). On a stuck production DB you can (1) mark `0010_admin_rbac.sql` as applied in `d1_migrations` if its schema is already in place, or (2) re-run the schema blocks via `wrangler d1 execute --file` and re-apply.
